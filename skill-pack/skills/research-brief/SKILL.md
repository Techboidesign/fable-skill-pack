# Research brief

Answer the question, not the topic. Stop when more searching stops changing the answer.

## 1. Frame (2 lines)
- **Question:** the decision this feeds.
- **Good enough means:** e.g. "3 options with price and one drawback each".

## 2. Budget
| Kind | Searches |
|---|---|
| Single fact | 1 |
| Compare a few options | 3-5 |
| Landscape / unfamiliar field | 5-8, then stop and report |

## 3. Search
- Short queries (1-6 words). Broad first, then narrow.
- Prefer primary sources: official docs, the company's own page, papers, regulators. Forums and listicles only as leads.
- **Fetch the page** before citing it; snippets mislead.
- For anything that changes (prices, versions, who holds a role): note the page's date.
- Two sources disagree -> one more search to resolve, or report both.

## 4. Write
```
## Answer
2-4 sentences, direct.
## Findings
| Claim | Source URL | Date | Confidence H/M/L |
## Disagreements / gaps
## What I'd check next (if it matters)
```

## Rules
- Every specific claim has a URL that was actually fetched this session. No URL -> mark "unverified" or drop it.
- Paraphrase; no long quotes.
- Separate **formal standards** (specs, laws, official docs) from **community consensus** (what practitioners say).
- Product recommendations are SEO-heavy: weight hands-on tests and official specs over "best of" lists.
- State what was NOT found. An honest gap beats a confident guess.
